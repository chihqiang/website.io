一个 Rust 写的版本管理器：把 Node、Go、Java、Python 收进同一个目录

chihqiang 2026-11-11 约 10 分钟 3730 字

一个项目跑 Node 18，另一个项目要 Node 22；Go、Java、Python 各自还有一套版本管理器。换台电脑，或者接手一个老项目，光是“把版本对齐”就要折腾半天。

lvm 想解决的就是这件事：用 Rust 写成的单个二进制，统一管理 Node.js、Go、Java、Python、Dart、Flutter、Kotlin、Rust 八种运行时，支持全局和项目级切换，所有版本都放在自己的目录里，不往系统目录里塞东西。

自动切换、隔离和清理

把 eval "$(lvm hook)" 加进 shell 配置后，进入包含 .lvmrc 或 .nvmrc 的目录就会自动切换。bash 用 PROMPT_COMMAND，zsh 用 chpwd，fish 监听 PWD 变化，PowerShell 则覆写 prompt。

这里有个细节做得比较克制：hook 调用的是 lvm use --no-default --skip-install。也就是说，进入目录不会悄悄改你的默认版本，也不会因为版本没装就突然开始下载。缺版本时它不会自动补，需要你自己执行 lvm install。

版本隔离也比较彻底：

  • Node.js 的 npm install -g 装进对应版本目录；
  • Go 的 GOPATH 指向当前版本的 packages，go install 的二进制不与其他版本共享；
  • Dart、Flutter 的 PUB_CACHE 按版本隔离；
  • Java、Kotlin、Rust 等通过 current 符号链接切换。

实现上有几个值得看的小设计

lvm 的代码量不大，但几个工程细节处理得比较认真。

用 trait 收敛语言差异。 每种语言实现 Language trait，必须提供 install 和 latest_version；目录结构、二进制名、版本前缀、bin 子目录都有默认实现，个别语言再覆盖。新增语言不需要改命令解析，注册进 LanguageRegistry 就能用。像 Rust 这种把工具链拆在 rustc/、cargo/ 子目录里的布局，就通过覆盖 is_installed 和 post_install 来处理。

安装和切换都尽量做到“要么成功，要么保持原状”。 版本先解压到临时目录，完成后再 rename 到正式目录；切换时先在旁边创建临时符号链接，再用 rename 替换。Unix 上这两步都是原子操作，不会出现“装到一半”的版本被当成可用版本。Windows 的符号链接替换要弱一些，代码里单独做了兼容。

解压时防路径穿越。 zip 和 tar.gz 都会去掉顶层目录，并拒绝绝对路径和包含 .. 的条目，避免压缩包把文件写到版本目录之外。

校验失败会重下，拿不到校验信息则告警跳过。 官方源提供校验和时会做 SHA256 比对，缓存文件校验不过就删掉重下。不过如果镜像没有提供校验信息，lvm 只打印警告然后继续安装，这一点在使用第三方镜像时需要留意。

多语言安装并行执行。 .lvmrc 里声明多个语言时，安装任务会并发跑；失败信息会汇总后一起返回，不会只报第一个错误。

CI 也覆盖了 Linux、macOS、Windows 三个平台，执行 fmt、clippy、构建和测试。

采用前需要知道的边界

lvm 目前还是 0.1.x，适合个人开发环境和对工具链要求不那么苛刻的团队，生产环境的关键构建链路建议先做验证。

几个实际使用中的注意点：

  • 自动切换不负责安装。 hook 带了 --skip-install，进入新项目发现版本缺失时，需要手动执行 lvm install。
  • Windows 的自动 hook 是受限的。 默认会提示不支持，只有显式指定 --shell powershell 才会生成对应脚本。
  • 全局包按版本隔离。 这不是 bug，而是设计选择；频繁切换版本的话，提前维护 default-packages 会省事很多。
  • 镜像的校验完整度取决于镜像本身。 如果很在意供应链安全，优先使用提供 SHA256 的官方源或可信镜像。

最后

如果你只写 Node，nvm 或 fnm 已经够用；lvm 的价值主要在“多语言 + 项目级锁定 + 统一目录”这三件事同时成立的时候。一个二进制、一个 .lvmrc、一次 lvm install，至少能让新机器上的环境准备少几个步骤。
